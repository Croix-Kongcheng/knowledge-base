# 云枢·低空知库

面向团队的团队共享知识空间，用于共同沉淀研究资料、项目记录和工作经验。空间归属简称为「团队知识空间」。

React + TypeScript + Tailwind CSS + ECharts 前端，Node.js + SQLite 服务端。适合香橙派部署，通过现有 FRPC 映射访问。Obsidian 深色、浅色和跟随系统三种主题均可使用。

此仓库提供完整应用源码、测试与通用部署示例。管理员身份、团队归属和目录过滤使用示例值，不包含实际用户资料、笔记、附件、账号数据库、初始化凭证、截图或历史备份。Git 提交使用通用作者身份。

## 运行

要求 Node.js 22.13 或更高版本（使用内置 `node:sqlite`）。

```bash
npm install
npm run build
PORT=5173 npm start
```

同一个进程同时提供 `dist/` 静态页面和 `/api/`，不需要另映射后端端口。生产数据默认存放在项目的 `data/`，可用 `DATA_DIR` 指定其他路径，构建不会清空该目录。

开发时启动两个终端：

```bash
npm run server:dev                   # 服务端默认 5175
npm run dev -- --port 5174           # Vite，/api 代理至 5175
```

## 账号与权限

- 注册和登录会真正校验密码。密码使用 scrypt 哈希保存，登录凭证使用 HttpOnly 会话 Cookie；不把密码或会话凭证写入 localStorage。
- 进入或刷新页面后，确认当前浏览器未登录时自动打开注册 / 登录窗口；已登录或暂时无法确认身份时不会误弹。关闭窗口后，本次页面的后台检查不会重复打扰；退出登录或会话失效后会再次提示。
- 笔记可供其他人阅读。登录成员可新建、导入、编辑和删除自己的笔记。
- 右上角账号菜单的“个人资料”可修改自己的显示名称 / ID 和头像，顶部账号、已有笔记作者与成员列表同步显示。选择本地图片后先预览，再点击“保存头像”；“恢复默认头像”也需要确认保存，取消窗口不提交头像草稿。
- 头像来源图片最大 20 MB，浏览器解码后居中裁为 512 × 512 方图、转为 PNG 上传；服务端限制 2 MB 并校验 PNG 结构、尺寸和有界解压。头像保存在独立账号数据中，换浏览器或服务重启后仍可用，不计入笔记附件统计。版本 URL 和 ETag 避免更换后继续看到旧头像。
- 空间成员中的图片头像可点击查看大图，支持手机屏幕；点击关闭、遮罩或按 Esc 返回，不会修改成员资料。
- 服务端只允许本人修改名称和头像，管理员也不能指定其他账号；账号内部 ID、邮箱及角色不随个人资料改变。
- 他人笔记默认只读，修改正文、标题、标签和分类都受同一权限约束。
- 管理员可以为任意一篇笔记开启或关闭“允许所有成员编辑”。开启后，登录成员可以编辑该篇笔记，作者保持不变；删除始终只有作者可操作。
- 管理员身份本身不会绕过作者编辑权限。管理员可以通过协作开关开放编辑。
- 服务端根据会话判断作者和角色，提交 ownerId、邮箱、作者名或 role 无法伪造权限；普通成员不能通过批量导入覆盖别人的文档。
- 修改带版本检查，遇到其他人已保存的版本会返回冲突，避免静默覆盖。未保存草稿会留在编辑器中。

唯一预留管理员使用示例身份 **Project Admin（admin@example.com）**。部署前请同步配置 `server/index.mjs` 的 `ADMIN_EMAIL` / `ADMIN_NAME` 与 `src/lib/workspace.ts` 的 `administrator`，团队显示名称在 `src/lib/space.ts` 和 `index.html` 中配置。普通注册不能抢注管理员邮箱。首次启动会在数据目录的 `admin-setup.json` 生成一次性初始化凭证（权限 600）；管理员通过私有 `/?setup=...` 链接设置密码。成功后凭证失效并删除，之后使用邮箱和密码登录。重启服务不会更换尚未使用的初始化凭证。

当前没有邮箱验证码或邮件找回密码服务；普通注册邮箱用作唯一登录标识。

## 阅读时间统计

- 仅管理员可见左侧“阅读统计”入口及统计页面；统计接口也会校验管理员身份，普通成员无法查询。
- 支持查看每位用户的累计阅读时间、每篇笔记的累计时间和阅读人数，以及每位用户读过哪些笔记、分别花费多少时间。用户统计和笔记统计均可进入对应明细，明细支持按用户、笔记和关键词组合筛选。
- 只有已登录用户真正显示的笔记处于浏览器前台且窗口获得焦点时，才具备计时资格。同一次连续停留必须超过 10 秒才开始累计，前 10 秒不计入；例如连续阅读 25 秒，累计 15 秒。
- 多篇笔记同时打开时只记录当前显示的一篇。切换笔记、进入编辑、切到后台或窗口失去焦点会结束本次计时；返回阅读后重新连续停留超过 10 秒才累计，后台笔记不会累加时间。
- 统计从此功能上线后开始收集，不追溯之前的阅读；刷新统计可查看最新累计结果。

## 笔记与 Obsidian 导入

- 全文搜索支持标题、正文、标签和作者；多级目录、收藏、列表/卡片视图可用。
- 页面先加载轻量目录和独立的登录状态，正文只读取当前打开的一篇；最近60篇文档及目录保存在浏览器读取缓存中，刷新时先显示缓存，再向服务器核对最新版本。缓存不参与身份验证或写入授权。全文搜索、反向链接由服务端按需查询，图谱、图表与公式渲染代码按页面加载。
- 目录与单篇详情使用 ETag 条件请求，未变化时返回304；JSON和静态资源支持gzip/Brotli压缩，带哈希的静态文件可长期缓存。
- 左侧以文档目录为主，可收起或拖动边缘调宽，宽度与收起状态会保留。点击整个文件夹行展开、收起，保持当前阅读内容；目录独立滚动，支持完整名称横向查看、搜索、全部收起和定位当前文档。手机上使用可关闭的抽屉。
- 右键文件夹可新建笔记、子文件夹、重命名或删除；右键笔记可重命名、删除。名称直接在目录中输入，Enter 确认、Esc 取消；新笔记创建后立即在页面中编写正文。空文件夹独立保存在服务器，刷新和其他设备均可查看。目录空白处也可创建根目录内容。
- 删除文件夹前显示子文件夹与笔记数量，确认后删除整个子树并清理无其他笔记引用的附件；包含他人笔记的文件夹不可整批删除，管理员也不能绕过作者删除权限。取消、网络失败不会丢失编辑草稿，成功后同步关闭已删除文档的标签并清理缓存。
- 文件夹重命名会事务更新全部子目录与笔记路径，保留文档 ID、正文和附件。目录中存在无权编辑的笔记时不可整批改名；普通成员也不能重命名他人创建的空目录。重名操作不会覆盖文件，笔记重命名与删除分别沿用编辑、作者删除权限。
- 顶部阅读设置可调整正文字号（12–24px）、行间距（1.2–3倍）、段间距（0–64px）与左右页边距（滑块0–480px，也可输入更大数值），即时应用于阅读和编辑并在当前浏览器保存，可恢复默认；窄屏自动收紧边距。深浅主题的选中文字均使用明确的前景色与背景色。大纲随阅读区实际宽度显示为右栏或可展开的顶部区域，长目录路径不会挤占大纲。支持反向链接、Markdown 表格、数学公式、图片及文件下载。
- 顶部导航与文档标签栏采用紧凑高度，滚动阅读时保持可见，大纲跳转会避开顶部栏。文档支持多标签：单击目录文件临时预览，斜体标签会被下一篇预览替换；双击文件或标签固定打开。支持单独关闭、键盘切换，标签状态在本次浏览器会话中保留。进入编辑会自动固定标签，离开未保存草稿前确认。
- 新建和编辑均直接在页面内容区进行，可修改标题、Markdown 和标签，支持 Ctrl/⌘+S 保存。已有文档直接从左侧目录拖入目标文件夹或根目录来移动；拖放受编辑权限与版本检查约束，同名目标不会被覆盖。预览保留附件引用，离开未保存草稿前会确认；文档 ID 不随标题和目录变化，已建立的内部链接继续有效。
- 编辑模式默认实时显示加粗、斜体、标题、图片和表格，光标进入对应内容后显示可编辑的 Markdown；点击表格即可修改其源码。支持 Ctrl/⌘+B 加粗、Ctrl/⌘+I 斜体和撤销重做，也可随时切换“源码”或整篇“预览”。
- 在编辑或源码模式下直接 Ctrl/⌘+V 粘贴剪贴板图片，也可点击图片按钮选择本地图片；图片独立保存在“附件/”，正文自动插入稳定引用，不嵌入 Base64。上传完成后即可预览与保存，上传失败保留正文草稿，取消编辑会清理本次未保存的图片，已保存附件不会被误删。
- 删除需要确认；最后一个文档引用消失时会清理对应服务端附件。
- 图谱使用实际笔记链接，可搜索、缩放、拖动、按目录着色，单次最多显示 800 个节点，搜索覆盖全部文档。

Windows 上推荐直接在网页选择整个 Obsidian 库的根文件夹，大型库不必先压缩；也支持 ZIP、多选 Markdown 和文件夹拖放。源文件不会被网页改动。

只想导入部分内容时，打开“关联导入”，选择来源知识库文件夹或 ZIP，再搜索、勾选一篇或多篇入口笔记，点击“分析关联内容”。程序只查找入口笔记直接关联的其他笔记，不再扩展关联笔记的出链。例如 A → B → C，只选 A 时导入 A、B；同时选 A、B 时导入 A、B、C。导入的每篇笔记直接引用的图片、PDF 等附件仍会保留；循环链接和共享附件只处理一次。确认前可查看入口数量、关联数量、附件数量及将导入的笔记路径，修改入口后需要重新分析。来源只在本地查找使用，点击确认后仅上传预览列出的笔记及其引用附件。浏览器无法自行读取未选择的 Windows 路径，缺失文件需重新选择包含它们的来源。

单批上限 **500 MB / 20,000 个支持的笔记和附件**，单篇 Markdown 上限 **10 MB**。关联导入按入口、直接关联笔记及它们引用的附件计算，不因来源中无关的大笔记或附件拒绝分析，也不读取或解压无关内容。普通整库模式仍检查全部支持文件的总量及 ZIP 展开大小。配置目录及不支持的文件不计入上传总量，未引用附件不上传。界面显示解析和上传进度，可在解析时取消；保存期间等待完成。

文件夹和编号沿用源结构；导入标题使用原始 Markdown 文件名（仅去掉扩展名），不会被正文一级标题或 frontmatter 的 `title` 覆盖。支持 frontmatter 分类与标签，`[[笔记]]`、`[[目录/笔记|别名]]`、Markdown 内联及引用式链接、本地图片和其他支持的附件。笔记之间转为稳定 ID 链接，附件保留独立稳定资源引用。同一批中多次引用同一附件只上传一次，上传按二进制流写入磁盘，不在笔记正文中嵌入 Base64。代码示例、注释、网页链接和当前笔记内的锚点不会扩展导入范围；同名且无法明确定位的链接会提示补充路径，不会随意选择一篇笔记。

再次导入时，以完整目录路径和文件名识别原笔记：路径相同则更新该篇内容和附件，保留原文档 ID、作者、协作设置、阅读统计、收藏和已打开的标签，不创建重复笔记；不同目录中的同名文件分别保存。导入批次的内部链接会指向最终保存的文档 ID。更新仍要求本人拥有编辑权限，他人只读笔记不能覆盖，管理员身份也不会绕过编辑限制；一批中如有路径冲突或无权更新的笔记，整批不会提交，并显示原因。

导入器演示了私有目录过滤，默认排除名为 `02私有资料`（兼容空格和分隔符）的目录。使用前请在 `src/lib/privacy.ts` 配置适合自己来源库的规则。缺失文件和同名歧义使用中性提示。

关联导入只扩展入口笔记的一层出链，不扩展反向链接或关联笔记的下一层笔记链接，也不扫描 PDF、Office 等附件内部的链接。当前不解析 Obsidian 插件语法、Canvas、嵌入笔记正文或块引用，也不保证跨文档章节锚点定位。未在来源中找到的文件仍需补充，不会静默改为其他同名文件。

## 旧浏览器笔记迁移

旧版浏览器 IndexedDB 和 localStorage 原数据会保留。用管理员账号在**原浏览器、原网址**登录，页面会检测尚未进入服务端的旧笔记并显示“迁移本机已有笔记”。

点击后会迁移文档及实际关联的 Blob / 旧版 Base64 附件，保留文档 ID、原目录和内部链接。旧浏览器迁移使用单独的管理员模式：服务端已有相同 ID 或规范化完整路径的文档会跳过，保留服务端现有内容；新文档指向这些旧 ID 的链接会转向实际服务器文档。已匹配的本地记录不再反复出现迁移提示，重复迁移会复用已迁移资源。失败时保留源数据，清理本批未提交附件，可重试；成功也不会删除或改写原浏览器数据。迁移成功后可从其他浏览器和账号阅读同一份知识库。

旧版本的展示身份不等于服务端账号，需要重新注册或通过管理员初始化链接设置密码。仅管理员能操作旧浏览器数据迁移，避免其他成员认领原有内容。

## 部署与备份

生产访问地址由部署者自行配置。可使用反向代理或 FRPC，将流量转发到服务监听的端口。仓库不包含实际服务器地址或隧道配置。

`deploy/knowledge-base.service` 是通用模板，默认应用目录 `/opt/knowledge-base`、数据目录 `/var/lib/knowledge-base`、Node.js 路径 `/usr/bin/node`。按实际环境修改路径，确保运行账号能够读写数据目录，再安装至 `/etc/systemd/system/knowledge-base.service`。服务独立运行，开机启动并自动重启。

```bash
systemctl status knowledge-base --no-pager
systemctl restart knowledge-base
journalctl -u knowledge-base -n 50 --no-pager
```

更新时运行 `npm run build` 再重启服务。备份时先停止服务，备份完整 `data/`（SQLite 数据库与附件目录必须一起保留），再启动服务；恢复也应一起恢复。初始化凭证属于管理员私有数据，不应公开分享。

旧版本导入的编号标题可用 `node scripts/restore-imported-numbered-titles.mjs --owner-email owner@example.com` 只读预演，确认后加 `--apply`。脚本仅处理该账号下创建后未修改、标题仍等于原导入一级标题的带编号文件；执行前在线备份数据库并在 `data/backups/` 保存私有恢复清单，逐行校验版本后恢复文件名，保留正文、附件、权限和原更新时间。重复执行不会再次修改已恢复的标题。

## 验证

```bash
npm test                 # 构建、隔离服务端测试、浏览器验收
npm run test:api         # 权限、版本冲突、持久化、221 MB 流式附件
npm run test:ui          # 需要先构建 dist
```

当前浏览器验收包括本人改名与身份保护、头像本地预览/保存/替换/恢复默认/跨浏览器显示与失败草稿/成员头像大图、多笔记预览替换/固定/关闭与草稿保护、阅读设置与持久化、深浅主题选区对比度、目录拖放/文件夹整批删除与同名冲突保护、侧栏收起与调宽、八级目录展开/滚动/搜索、桌面和手机布局、页面内编辑、真实账号 CRUD、三账号协作开关与撤权、导入图片/PDF/内部链接、关联导入的一层关联/多入口并集/循环与共享附件去重/搜索和来源切换/取消不写入、ZIP 无关内容保持压缩与选中内容限额、旧 IDB 迁移失败重试及管理员初始化。每个用例启动独立服务与临时数据库，结束清理，测试账号不会进入正式知识库。导入器隐私检查由 Vite 提供源模块，所有 API 请求使用空测试数据。

早期 `app.spec.ts`、`import.spec.ts`、`large-import.spec.ts`、`workspace.spec.ts` 是纯浏览器 IndexedDB 原型的历史快照，当前默认验收已由服务端场景替代，不再直接运行这些旧数据模型的断言。
