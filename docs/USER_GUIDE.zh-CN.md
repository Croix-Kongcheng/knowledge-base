# 云枢·低空知库使用指南

这份指南适用于本仓库公开版本。普通成员可以从“快速开始”读起；负责安装和维护的人请继续阅读后面的部署、初始化与备份步骤。部分界面仍使用“知屿”名称，指的是同一个应用。

## 1. 快速开始

已经有人部署好知识库时，不需要安装 Node.js 或下载源码，直接用浏览器打开管理员提供的网址。

1. 点击右上角账号菜单，选择“注册 / 登录”。新用户在“注册账号”页填写名字、邮箱、密码和确认密码；已有账号切换到“登录账号”。
2. 在左侧“文档目录”点击一篇笔记开始阅读。查找内容时使用顶部搜索框，或按 `Ctrl / ⌘ + K`。
3. 点击目录标题旁的“新建笔记”加号，填写标题、分类、标签和正文，点击“保存笔记”。
4. 已有 Markdown 或 Obsidian 笔记时，点击“导入笔记”，选择文件夹或 ZIP，检查预览后再导入。
5. 要修改自己的笔记，打开后点击“编辑”，完成后点击“保存修改”或按 `Ctrl / ⌘ + S`。

当前版本需要手动保存。看到保存成功并返回阅读页面后，本次修改才已提交到服务器；不要把未保存的编辑器当作自动备份。

## 2. 账号与共享权限

注册密码至少需要 8 个字符。邮箱是登录标识，目前没有邮箱验证码和邮件找回密码功能，请记住注册邮箱和密码。管理员使用部署者配置的专属初始化入口启用账号，不能通过普通注册认领管理员身份。

这个应用是共享知识空间，笔记默认允许访客阅读。登录账号用于标识作者和校验写入权限，不能把个人账号理解成独立的私有笔记库。

| 操作 | 访客 | 普通成员 | 管理员 |
| --- | --- | --- | --- |
| 阅读笔记和查看附件 | 可以 | 可以 | 可以 |
| 新建、导入笔记 | 不可以 | 可以 | 可以 |
| 编辑、重命名、移动自己的笔记 | 不可以 | 可以 | 可以 |
| 编辑他人的笔记 | 不可以 | 该笔记开启协作后可以 | 该笔记开启协作后可以 |
| 删除笔记 | 不可以 | 只能删除自己的笔记 | 只能删除自己的笔记 |
| 调整单篇笔记的协作开关 | 不可以 | 不可以 | 可以 |
| 查看阅读时间统计 | 不可以 | 不可以 | 可以 |

管理员可以在笔记阅读页打开“允许所有成员编辑”。打开后，已登录成员可以修改这篇笔记，原作者不变；关闭后恢复为仅作者可编辑。协作权限不包含删除他人笔记的权限。

多人同时编辑同一篇笔记时，保存可能提示版本冲突。请先把当前草稿复制到本地，重新打开最新版本，再合并需要保留的内容。保存失败时草稿留在当前编辑器中，直接刷新页面可能丢失草稿。

## 3. 阅读、查找与收藏

### 找到需要的笔记

- **左侧目录**：点击文件夹行展开或收起，点击文件阅读。目录内的搜索用于查找文件和文件夹名称。
- **顶部搜索**：检索标题、正文、标签和作者；按 `Ctrl / ⌘ + K` 可以快速定位搜索框。
- **全部文档**：点击“文档目录”标题旁的列表图标“查看全部文档”，可切换列表、卡片视图，并按分类筛选。分类筛选包含子文件夹。
- **标签管理**：点击标签云中的标签查找相关笔记。标签的新增、修改和移除，需要进入有编辑权限的笔记，在“添加标签”中操作。

目录过窄时，可以拖动侧栏边缘调宽；点击顶部侧栏按钮可以收起或展开。手机上使用同一按钮打开目录抽屉，选好文档后可关闭抽屉继续阅读。

### 同时打开多篇笔记

单击目录文件会打开一个标题为斜体的临时预览标签；再单击另一篇文件时，会替换这个预览。双击文件、双击标签或点击固定图标，可以保留该标签，方便对照阅读。进入编辑也会自动固定当前标签。

每个标签可以单独关闭，标签状态保留在本次浏览器会话中。焦点位于文档标签上时，可以用左右方向键切换、`Home / End` 跳到首尾、`Delete` 关闭、`Ctrl / ⌘ + Enter` 固定预览。

### 调整阅读体验

正文支持表格、数学公式、图片和附件链接。可展开文档大纲，点击标题跳转；文末的反向链接用于查看哪些笔记链接到了当前文档。

顶部“阅读设置”可以调整字号、行间距、段间距和左右页边距，也可以“恢复默认”；设置同时作用于阅读和编辑。主题可选择“Obsidian 深色”“Obsidian 浅色”或“跟随系统”。

点击文档或列表中的星标可以收藏；从“知识概览”的“我的收藏”进入收藏列表。**收藏、阅读设置和主题属于当前浏览器的偏好，收藏目前不会随账号跨设备同步。** 笔记正文、账号资料和附件则存放在服务器上。

## 4. 新建、编辑与整理笔记

### 创建并保存

点击“新建笔记”，填写“笔记标题”，选择“知识分类”，在“添加标签”中用逗号分隔多个标签，再编写正文。标题和正文都不能为空。完成后点击“保存笔记”。

也可以右键某个文件夹，选择“新建笔记”。这种方式会先创建目录条目，再进入正文编辑；如果取消编辑后仍看到空笔记，可以通过右键菜单删除它。

### 选择编辑模式

| 模式 | 适合做什么 |
| --- | --- |
| 编辑 | 一边写一边查看加粗、标题、图片和表格等效果；光标进入对应内容后编辑 Markdown |
| 源码 | 查看和修改完整的 Markdown 原文 |
| 预览 | 检查整篇文章最终的阅读效果 |

在实时“编辑”模式的正文中，`Ctrl / ⌘ + B` 加粗、`Ctrl / ⌘ + I` 斜体、`Ctrl / ⌘ + Z` 撤销、`Ctrl / ⌘ + Shift + Z` 重做；也可以使用编辑器上方的格式按钮。保存使用 `Ctrl / ⌘ + S`。

下面是一份可直接尝试的 Markdown：

```markdown
# 项目记录

## 本周进展

- 完成第一轮资料整理
- **下一步**：补充验证结果

| 事项 | 状态 |
| --- | --- |
| 资料归档 | 已完成 |
| 结果复核 | 进行中 |

行内公式：$E = mc^2$

[参考资料](https://example.com)
```

### 插入图片

在“编辑”或“源码”模式下，直接粘贴剪贴板中的图片，或点击工具栏的“插入图片”选择本地文件。等待“正在上传图片…”结束，再保存笔记。

编辑器图片上传支持 PNG、JPEG、GIF、WebP、AVIF 和 BMP。图片会保存为独立附件，正文保留引用。取消编辑时会清理本次尚未保存的图片；原笔记已有的附件不会因此删除。

### 整理目录

- 右键文件夹，可以“新建笔记”“新建文件夹”“重命名”或“删除文件夹”；目录空白处也可以创建根目录内容。
- 输入文件或文件夹名称时，按 `Enter` 确认、`Esc` 取消。
- 移动已有文档时，把左侧文件拖到目标文件夹；拖动时也可使用“移到知识库根目录”。已有笔记的编辑器只显示位置，不能通过分类下拉框移动。
- 同一位置出现重名时，程序会拒绝操作，不会自动覆盖已有文档。重命名和移动会保留文档 ID，已有内部链接继续可用。

删除笔记或文件夹需要确认。删除文件夹会同时删除整个子目录树及其中的笔记；其中包含无权删除的内容时，操作会被拒绝。页面目前没有回收站，删除后需要依靠服务器备份恢复；没有其他文档引用的附件也会被清理。

## 5. 导入 Markdown 与 Obsidian

点击“导入笔记”后，根据来源选择方式：

| 导入方式 | 适用情况 |
| --- | --- |
| 选择文件夹 | 导入整个 Obsidian 库或一个资料目录，大型库优先使用这种方式 |
| ZIP 整库导入 | 已经把笔记和附件一起打包为 ZIP |
| Markdown 文件 | 只导入少量 Markdown；需要同时选中它们引用的附件 |
| 关联导入 | 只选择部分入口笔记，并带入它们直接链接的笔记及附件 |

### 整库或文件夹导入

1. 选择库的根文件夹，或包含笔记与附件的 ZIP。也可以拖放到导入区域。
2. 等待解析，查看笔记数、附件数和待补充链接等提示。
3. 希望保持原来的多级目录时，保留“保留原有目录分类”。选择其他分类会把本批笔记统一放到该目录，不保留原子目录层级；本批同名文件会添加数字后缀以区分。
4. 检查导入预览，点击“导入 N 篇笔记”。
5. 保存完成后，在左侧目录打开笔记，确认正文、图片和内部链接。

程序不会修改本机来源文件。导入标题使用 Markdown 文件名，去掉扩展名；正文的一级标题或 frontmatter 中的 `title` 不会替换文件名。只有笔记实际引用的附件才会上传，未引用附件不计入知识库。

### 只导入相关资料

1. 选择“关联导入”，点击“选择来源文件夹”或“选择来源ZIP”。
2. 搜索并勾选一篇或多篇“入口笔记”。来源目录要包含可能用到的关联笔记和附件。
3. 点击“分析关联内容”。
4. 核对入口笔记、关联笔记、附件、待补充链接及将导入的路径清单。
5. 点击“导入 N 篇笔记”。修改入口勾选后，需要重新分析。

关联导入只展开入口笔记的**一层出链**。例如 `A → B → C`：只选 A 时导入 A、B；同时选 A、B 时才会包含 C。A、B 直接引用的图片、PDF 等附件仍会保留。不会沿反向链接继续扩展，也不会扫描附件内部的链接。

关联导入在确认前仅使用本地来源查找内容，确认后上传预览列出的笔记及引用附件。浏览器只能读取你主动选择的文件，不能根据一个电脑路径自动查找其他目录。

### 大小限制与再次导入

单批最多 **500 MB、20,000 个支持的笔记和附件**，单篇 Markdown 最多 **10 MB**。关联导入按实际选中的笔记及其关联内容计算；普通整库导入会检查全部支持文件的总量。解析期间可取消，进入保存阶段后请等待完成。

再次导入时，**完整目录路径和文件名相同**的笔记会更新原内容，保留文档 ID、原作者、协作设置和阅读统计，原有收藏及打开标签仍指向同一篇文档。不同目录中的同名文件分别保存。如果你已在网页中移动或重命名笔记，再按旧路径导入，就可能得到另一篇文档。

只能更新自己有编辑权限的笔记。一批文件中出现路径冲突或无权更新的条目时，整批不会提交；先处理提示，再重试。

公开版默认演示排除 `02私有资料` 目录，兼容相应的空格和分隔符写法。部署者应在 `src/lib/privacy.ts` 配置适合自己来源库的规则；该规则不代表自动识别所有隐私内容，导入前仍要确认预览中的资料适合共享。

Obsidian 的 `[[笔记]]`、带路径或别名的链接、常见 Markdown 链接和本地附件可以识别。插件语法、Canvas、嵌入整篇笔记正文、Obsidian 块引用链接及跨文档章节定位不保证兼容。同名目标无法确定或文件缺失时，请补充明确路径或重新选择完整来源。

## 6. 个人资料、图谱与阅读统计

**个人资料**：打开右上角账号菜单 →“个人资料”。修改显示名称后点击“保存名称”；更换头像时先选择图片、检查预览，再点击“保存头像”。“恢复默认头像”也需要保存。取消不会提交头像草稿。名称与头像分别保存，内部账号 ID、邮箱和角色不会改变。头像来源图最大 20 MB，会居中裁剪；成员列表中的图片头像可以点击放大查看。

**知识图谱**：点击左侧“知识图谱”，拖动平移、滚轮缩放、点击节点打开笔记。“图谱设置”中可以搜索、显示孤立文档和按目录着色。图谱依据实际笔记链接生成，单次最多显示 800 个节点，搜索覆盖全部文档。

**阅读统计**：仅管理员可见左侧“阅读统计”。页面提供“用户统计”“笔记统计”“阅读明细”，可以进入明细、按成员或笔记筛选，再点击“刷新统计”查看最新结果。

计时需要已登录，当前笔记真正显示在浏览器前台，且窗口获得焦点。连续停留超过 10 秒才开始累计，前 10 秒不计入，例如连续阅读 25 秒累计 15 秒。切换笔记、进入编辑、切到后台或窗口失焦都会结束本段计时；返回后重新计算连续停留，后台打开的其他笔记不会累计。统计不追溯功能启用前的阅读。

## 7. 安装与首次部署

以下命令面向 Linux 和香橙派。已有可用站点的普通成员可以跳过本节。示例使用通用目录、示例账号和本机地址，不包含实际部署信息。

### 获取源码并运行

安装 Node.js **22.13 或更高版本**及 npm，先用 `node --version` 确认版本。下载本仓库源码，在项目目录中执行：

```bash
npm ci
```

第一次启动前，按需要配置以下内容：

| 文件 | 配置项 |
| --- | --- |
| `server/index.mjs` | `ADMIN_EMAIL`、`ADMIN_NAME`：管理员示例身份 |
| `src/lib/workspace.ts` | `administrator` 的邮箱、名称及头像缩写，与服务端保持一致 |
| `src/lib/space.ts`、`index.html` | 团队名称、页面标题和描述 |
| `src/lib/privacy.ts` | 导入时排除的目录规则 |

仓库中的 `admin@example.com` 和 `Project Admin` 是示例值。管理员身份应在首次启动、创建数据库之前配置；改源码不会自动修改已有数据库中的管理员账号。真实身份和部署定制请保留在自己的部署副本中，不要直接提交到公开仓库。

构建并在本机体验：

```bash
npm run build
HOST=127.0.0.1 PORT=5173 npm start
```

打开 `http://127.0.0.1:5173/`。需要让局域网其他设备访问时，使用 `HOST=0.0.0.0 PORT=5173 npm start`，在其他设备浏览器中填写服务器的局域网地址与端口。公网地址、反向代理和 FRPC 映射由部署者自行配置；页面和 `/api/` 必须转发到同一个应用服务。

`npm start` 不指定 `PORT` 时默认监听 **5175**；本指南和 systemd 模板显式使用 **5173**。生产数据默认保存在项目 `data/`，可用 `DATA_DIR` 改为独立路径。项目不会自动读取 `.env`，启动参数要通过命令行环境变量或 systemd 配置设置。

### 启用管理员账号

首次启动后，实际数据目录中会生成 `admin-setup.json`。在服务器自己的私有终端中、使用有读取权限的账号运行下面的代码；按实际情况修改文件路径和知识库地址：

```bash
node --input-type=module <<'NODE'
import { readFileSync } from 'node:fs';

const { token } = JSON.parse(readFileSync('./data/admin-setup.json', 'utf8'));
const link = new URL('http://127.0.0.1:5173/');
link.searchParams.set('setup', token);
console.log(link.href);
NODE
```

上例适用于项目根目录、默认数据目录和本机浏览器；systemd 模板的数据文件路径是 `/var/lib/knowledge-base/admin-setup.json`，远程浏览器要使用它实际能访问的站点地址。

在自己的浏览器打开生成的链接，设置并确认管理员密码，完成后会自动登录。一次性链接包含管理员凭证，不要贴入公开文档或 issue。成功后初始化文件会删除，链接随即失效；未使用的链接在服务重启后仍有效。已经启用管理员时，没有该文件属于正常情况。

### 设置开机启动

项目提供 `deploy/knowledge-base.service`。安装前先按实际环境调整模板中的应用目录、Node.js 可执行文件路径、端口和数据目录，并确认运行账号能读写数据目录。模板默认应用目录 `/opt/knowledge-base`、Node.js 路径 `/usr/bin/node`、数据目录 `/var/lib/knowledge-base`。

如果刚才以前台方式启动过服务，先在对应终端按 `Ctrl+C` 停止，避免两个进程占用同一端口。前台示例使用项目 `data/`，模板使用 `/var/lib/knowledge-base`；直接切换会创建全新的知识库。要保留体验阶段的账号与笔记，请先停止所有实例，完整迁移原数据目录到新路径，或将模板的 `DATA_DIR` 指向原数据目录，再检查运行账号权限。

确认源码已放到模板指定位置并完成构建后，执行：

```bash
sudo install -m 644 deploy/knowledge-base.service /etc/systemd/system/knowledge-base.service
sudo systemctl daemon-reload
sudo systemctl enable --now knowledge-base
sudo systemctl status knowledge-base --no-pager
```

模板未设置 `User=`，由系统服务默认账号运行。若改为专用账号，还要相应设置数据目录权限。

### 开发调试

在项目目录打开两个终端，分别执行：

```bash
# 终端一：API 服务，默认端口 5175
npm run server:dev
```

```bash
# 终端二：前端，API 代理到 5175
npm run dev -- --port 5174
```

开发时访问 `http://127.0.0.1:5174/`。`npm run preview` 只预览静态前端，不能替代负责账号和数据库的服务端。

## 8. 更新、备份与恢复

GitHub 仓库保存源码，不包含实际账号、笔记和附件。重新下载源码不能恢复知识库数据。

### 备份

先确定实际使用的 `DATA_DIR`。默认前台运行是项目 `data/`，systemd 模板是 `/var/lib/knowledge-base`，二者不要混淆。数据库、头像、阅读统计、附件目录及其他数据文件需要一起备份。

下面的例子适用于 systemd 模板路径。停服后完整归档，再启动服务；备份存放在数据目录以外：

```bash
sudo install -d -m 700 /var/backups/knowledge-base
sudo systemctl stop knowledge-base
sudo tar -C /var/lib -czpf "/var/backups/knowledge-base/backup-$(date +%Y%m%d-%H%M%S).tar.gz" knowledge-base
sudo systemctl start knowledge-base
```

确认归档成功，并把备份保存在私有位置。若归档失败，也应启动服务并排查错误。SQLite 的 WAL 模式下，不要在服务运行时只复制单个 `knowledge.sqlite` 文件作为备份；`data/`、备份压缩包和初始化凭证都不应上传到公开仓库。

### 更新应用

先完成数据备份，再将新版源码更新到自己的部署目录，保留本地配置和实际数据目录。在项目目录执行：

```bash
npm ci
npm run build
sudo systemctl restart knowledge-base
sudo systemctl status knowledge-base --no-pager
```

仅重新构建前端不会清空数据目录。更新后检查登录、打开一篇笔记和查看图片，确认应用正常。

### 从备份恢复

1. 停止服务。
2. 将当前数据目录另行保留，便于恢复失败时退回。
3. 把完整备份恢复到配置的 `DATA_DIR`，不要把旧、新数据库和附件混合覆盖。
4. 检查运行账号的读取和写入权限。
5. 启动服务，检查账号、目录、正文和附件。

恢复到哪个备份，就会回到该备份时的数据状态。备份之后新增或修改的内容不会自动保留。

### 迁移旧版浏览器笔记

如果使用过仅在浏览器保存数据的旧版本，请在**原浏览器、原网址**用管理员账号登录。页面检测到旧数据后，会显示“迁移本机已有笔记”，按提示迁移即可。

迁移会保留原文档及关联附件，已有相同 ID 或完整路径的服务器文档会跳过，不覆盖现有内容。迁移不会删除旧浏览器的源数据。换了浏览器或网址看不到旧记录时，应回到原来的浏览器和访问地址操作。

## 9. 常见问题

| 现象 | 处理方法 |
| --- | --- |
| 看得到笔记，但没有编辑按钮 | 确认已经登录；检查是否是本人创建，或请管理员为这篇笔记开启“允许所有成员编辑” |
| 保存提示版本冲突 | 先复制草稿，重新打开最新版本，再合并修改 |
| 导入后缺少图片或链接目标 | 重新选择包含关联笔记和附件的完整来源；单独选 `.md` 时同时选择附件；同名笔记使用明确路径 |
| 再次导入出现另一篇笔记 | 对照完整目录与文件名，检查是否在网页或来源中移动、改名 |
| 导入按钮不可用 | 等待解析完成；关联导入需要先选入口并点击“分析关联内容”；查看错误提示 |
| 换浏览器后收藏或阅读设置不同 | 这些属于当前浏览器的偏好，尚不随账号同步 |
| 刷新后找不到未保存正文 | 当前没有自动保存草稿；编辑后需要点击保存或使用保存快捷键 |
| 管理员链接无效或初始化文件不存在 | 检查账号是否已启用、链接是否已使用，或是否访问了另一套服务和数据目录 |
| 页面能打开，但注册、保存或加载正文失败 | 部署者检查 API 服务及 `/api/` 转发，确认不是只运行了静态预览 |
| 阅读时间没有立刻增加 | 确认已登录、当前笔记在前台且窗口获得焦点，连续停留超过 10 秒，再刷新统计 |

部署者可在服务器上执行以下命令定位运行问题，端口按实际配置调整：

```bash
node --version
curl http://127.0.0.1:5173/api/health
sudo systemctl status knowledge-base --no-pager
sudo journalctl -u knowledge-base -n 50 --no-pager
```

健康接口正常返回 `{"ok":true}`。端口占用时检查 `EADDRINUSE` 日志；数据写入失败时检查数据目录权限和磁盘空间。忘记密码时，当前没有自助邮件找回入口，不要通过删除整个数据目录尝试重置账号。
